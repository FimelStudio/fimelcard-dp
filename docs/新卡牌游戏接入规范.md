# 新卡牌游戏接入规范

适用 Minecraft Java 26.2。新增游戏先核对唯一的 `<game_id>`、独立命名空间 `<game_ns>` 和短前缀 `<p>`；已用编号见[文档索引](README.md)。编号可按作者要求预留，不擅自补位或重排；19 号为同伴制作的命悬一线（`ito`），围棋为 20 号，卡坦岛为 21 号。

## 模块与实例边界

`cardtable` 管理桌面、座位、人数、菜单、结束投票、公共动画及游戏分派；游戏模块管理牌组、回合、玩家状态、计分、设置与专属清理。复用公共发牌及座椅接口，不复制维护逻辑，不删除或直接改造通用控制器、座椅。

控制器为 `@e[type=minecraft:marker,tag=ct.controller]`，游戏入口默认以它为执行者、以桌心为执行位置。

| 控制器记分项 | 含义 |
| --- | --- |
| `ct_id` | 服务器内唯一桌号 |
| `ct_state` | 0 大厅，1 游戏中 |
| `ct_game` | 当前游戏编号 |
| `ct_capacity` | 桌型容量 4 或 8 |
| `ct_joined` | 当前参与人数 |
| `ct_start` | 开局成功握手，初始 0，游戏成功后置 1 |
| `ct_votes` | 当前有效结束票数 |

参与玩家带 `ct.player`，其 `ct_id` 为桌号、`ct_seat` 为实际座号。八座按北 1～2、东 3～4、南 5～6、西 7～8 顺时针排列。人数和座号分开处理：五人局也可能坐在 6～8 号座，发牌、邻座、提示、投票和显示均须跳过空座。游戏中下马不代表退出。

需要按阵营换座时，先计算并冻结所有目标座号，再全部下座、统一更新实际座号与游戏座号，最后分别骑乘公共座椅；不能一边移动一人，一边用正在变化的选择器决定另一人。复核目标座号及真实乘客均唯一；重载沿用已有阵营恢复落座，不重新随机。阵营、行动顺序与实际座号分开保存，人机不伪造玩家实体。

所有长期实体须带专属标签和桌号，清理同时校验两者。距离仅用于缩小范围，不能代替实例归属；跨刻临时状态也须绑定桌号。同步临时标签应在同一函数链内完成清旧、标记、使用和移除。

```mcfunction
# 控制器定位本桌玩家；不要仅用 nearest 认定归属
scoreboard players operation #ctx_id <p>_ctx = @s ct_id
execute as @a[tag=ct.player] if score @s ct_id = #ctx_id <p>_ctx run ...
```

专属记分项、标签、storage 统一使用本游戏前缀或命名空间，例如 `<p>_state`、`<p>.controller`、`<game_ns>:runtime`。记分项目标名建议不超过 16 字符。

## 规则状态与保密

真实牌组或身份、已公开信息、临时展示分开保存。规则以后台状态为准，HUD、对话框、桌面展示、聊天与动画只读取该接收者有权知道的信息；旁观展示不得复用某位玩家的私有手牌。Dialog 中的玩家姓名须先解析为真实文本组件，可参考花火的名字处理，不能直接显示选择器字符串。

多副牌须区分每张实体牌的唯一 ID、牌面类型及用于比较的牌型；同点叠牌仍须能逐张选择，扣牌与清理按真实 ID 执行。百搭存在多种合法解释时显式选定并记录，不由界面猜测规则结果。

隐藏棋子等未知信息不得被合法走法提示或人机偷看。模拟只用公开状态；真实提交到公开时点才揭示身份，被吃暗子等仍未公开的信息继续保密。计分估算与正式结算分开标注，需要双方确认的结果不能自动当作最终裁定。

交易报价不得通过成功／失败探查对手的私有库存：发起时只校验发起者是否有能力支付，接受时再原子核对双方库存和报价编号。公开可推算的生产可显示实际资源图标，秘密交易或抽牌动画使用中性袋、牌背等表现，不能泄露未公开类型。

## 生命周期接口

推荐沿用 `function/game/`、`player/`、`settings/`、`rules/`、`deck/`、`deal/`、`round/`、`debug/` 的现有职责划分。

| 接口 | 执行者与要求 |
| --- | --- |
| `game/init_table` | 控制器；幂等，只修正缺失或越界的持久设置，不能重置活跃对局 |
| `game/start` | 控制器；自行检查人数、快捷栏等条件，失败保持 `ct_start=0` 并返回失败，全部初始化成功后置 1 |
| `game/finish` | 控制器；锁定结束状态、展示结果、清理临时状态，最后返回大厅；可按规则保留终局 |
| `game/end_vote` | 控制器；通用层已判定票数，执行一次提前结束流程 |
| `game/abort` | 控制器；任意阶段可安全中止，完整清理后返回大厅 |
| `admin/abort` | 玩家；定位同维度 8 格内最近一场本游戏，无目标提示并返回失败，切换执行者和位置后调用 `game/abort` |
| `game/player_left` | 控制器；决定离线后继续、淘汰或中止的行为 |
| `player/clear_state` | 玩家；仅清理该玩家的专属物品、标签和临时分数 |
| `settings/open` | 控制器；接收玩家为 `ct.settings_actor` |
| `rules/show` | 控制器；接收玩家为 `ct.rules_actor` |

开局时复制 `ct_id`、实际 `ct_seat` 到游戏运行状态；需要换座时按上文流程同步，桌号归属不变。人数必须同时满足本游戏范围与桌型容量；游戏加载入口不得替代开局入口。

结束流程须防重复进入。清理专属道具、掉落物、活动交互、私有 HUD、文字及公共发牌动画；不保留终局的游戏同时清理牌堆与桌面展示，移除其活动控制器标签，最后调用：

```mcfunction
function cardtable:animation/deal/clear
function cardtable:game/return_lobby
```

不得删除方块桌、玩家装饰、`ct.controller`、`ct.seat` 或其他桌状态。若清理期间调用人数重算等通用维护，先锁定结束状态，避免重新触发结束投票。不要在结算过程中重复初始化计时器。

保留终局时只保留必要棋面、公开记录和复盘入口，关闭继续落子、行动道具与活动计时；大厅文字不能遮挡棋面。重建展示不重摆棋局，仅在明确重开、切换游戏或移除牌桌时清除终局；保留的实体和标记仍须能被移桌、切游戏流程完整清理。

保留终局须有持久标记（如 `data.<game_ns>.review`），大厅初始化、设置预览与 `/reload` 均识别它，不能把终局重新生成成开局预览。改变下一局布局设置不擦除当前终局；新开局明确移除标记并建立新状态。结束时一并清空动画事件队列、临时飞行物和延迟回调，避免旧动画在大厅继续覆盖棋面。

## 注册点

新增游戏时逐项检查以下文件。选项、分派、编号校验与已注册编号一致，预留编号不能变成可开局的空选项：

| 文件（相对 `data/cardtable/function/`） | 更新内容 |
| --- | --- |
| `load.mcfunction` | `#game_count ct_ctx` |
| `menu/picker/show4`、`show8`、`open`、`handle` | 选择按钮、人数提示、提交值与编号校验 |
| `menu/select_game` | 切换消息及日志 |
| `menu/game_name_<game_ns>`、`menu/render` | 大厅名称与未知编号兜底 |
| `game/init_selected` | `game/init_table` 分派 |
| `game/start` | 开局分派与握手 |
| `game/open_settings` | 设置入口分派 |
| `game/open_rules` | 规则入口分派 |
| `vote/finish` | 已达门槛后的 `game/end_vote` 分派 |
| `table/remove` | 活跃对局的 `game/abort` 分派 |
| `game/remove_offline_player` | 玩家专属清理分派 |

表中省略的函数文件扩展名均为 `.mcfunction`。在 `data/minecraft/tags/function/load.json`、`tick.json` 各登记一次本游戏总入口，并更新根 README 的游戏链接及文档索引。游戏人数变化须同步两种桌型的菜单和规则。

## 设置与交互

设置最终保存在本桌控制器上，不能用全局 storage 充当所有桌的持久设置。默认采用单页、修改即生效的界面，通过按钮或可点击选项直接提交，不再逐项跳页保存。原版 `number_range` 没有值变化提交回调；需要滑块时须提供同页确认，不能把拖动写成即时生效。仅补齐缺失或越界的默认值，保留用户已有的有效设置；开局后锁定的选项明确限制在大厅修改。

打开界面时保存桌号、游戏或阶段 epoch、窗口 nonce 与本次加载代号，并给玩家启用独立 trigger。提交复核参与身份、原桌归属、控制器、游戏、阶段及全部代号；一次性动作成功后消费 nonce 或更新版本，拒绝重放。切桌、开局、离座、回合变化、重载后的旧窗口须拒绝；设置还须验证大厅状态和取值范围。多个输入编码为整数时，记录编码方式并检查边界。

新增游戏默认允许无 OP 玩家完成开局、设置和整局操作；交互及 Dialog 通过 trigger 提交，不把有权限要求的 `/function` 作为日常按钮。规则使用 `pause:false` 的只读 Dialog，说明人数、操作、胜负、计分及特殊情况；管理与 Debug 命令另列。

回合操作道具按“当前是否有待完成操作”发放，不能只看轮到谁；投骰、移动等动画阶段按规则回收，常驻对局菜单独立保留。质疑、悔棋、求和等响应有独立的待答对象和入口，不能因不是自己的回合而收掉响应入口或套用行棋权限。

发放、Q 丢出后返还、状态刷新及逐刻补发共用资格检查，核对桌号、参与身份、阶段与待办状态，不依赖与牌桌的距离。只补缺失道具，回收和掉落物匹配专属数据及所有者；不覆盖普通物品，不把道具交给邻桌或其他玩家。布局与腾空格位写入游戏文档。

| `ct_kind` | 通用用途 |
| --- | --- |
| 11～18 | 座椅，10 加座号 |
| 21 / 22 / 23 | 切换游戏 / 开始 / 设置 |
| 30 / 31 | 结束投票 / 常驻规则 |

新增通用交互须登记唯一编号，提供右键与攻击两个 advancement，并在奖励函数开头撤销它们。游戏专属按钮使用自己的 advancement 和状态，不重复生成通用规则按钮。

结束投票由通用层按当前在线真人统计：四座桌为 `min(3, 人数)`，八座桌为 `floor(人数/2)+1`；重复投票和已离桌者的票不得计入。游戏直接接收通过后的结束回调。

## 卡牌与公共发牌动画

卡牌逻辑依据游戏专属 `custom_data`，`item_model` 仅控制外观、`item_name` 仅控制名称。清理时按专属数据匹配，不能误删普通纸或其他游戏物品。

先验证并原子提交规则结果，再播放表现动画；动画期间限制重复输入，完成回调只解锁或推进表现，不能再扣牌、重复计分。骰值、抽牌或身份随机结果只产生一次并保存，模型最终朝向须与已定结果一致。胜利烟花复用内置 SK Firework，在胜者实际位置触发。

连续动画按本桌队列保存事件快照，记录已确定的目标、拥有者、实际座号、数量及骰值等表现参数；排队后不再读取会被下一次操作覆盖的全局临时字段。生产事件按实际发放量入队，库存不足时不演示未发出的资源。动画中点击不得积压为解锁后的新操作；重载可丢弃表现队列并从已提交棋面重建，不回滚或重复提交规则结果。

公共入口位于 `cardtable:animation/deal/`，调用者必须是本桌控制器且位于桌心：

| 入口 | 作用 |
| --- | --- |
| `box/spawn` | 在桌心上方生成小牌盒 |
| `box/grow` / `box/shrink` | 10 刻内放大 / 缩小，生成后至少隔 1 刻再放大 |
| `box/clear` | 清除本桌牌盒 |
| `spawn_card` | 生成唯一待配置物品，标记 `ct.new_dealt_card` |
| `sound` | 向本桌玩家播放发牌音效 |
| `launch {seat:N}` | 设置接收者与动量，送往实际 N 号座 |
| `clear` | 清理本桌公共动画与临时状态 |

游戏负责牌面、牌数、顺序、间隔及完成回调；通用 tick 负责飞行与 6 刻兜底送达，不得另写重复维护。

```mcfunction
function cardtable:animation/deal/spawn_card
item replace entity @e[type=minecraft:item,tag=ct.new_dealt_card,distance=..2,limit=1] contents with minecraft:paper[minecraft:item_model="<model>",minecraft:item_name="<name>",minecraft:custom_data={<game_ns>:{card:1b,id:1}},minecraft:max_stack_size=1]
function cardtable:animation/deal/sound
function cardtable:animation/deal/launch {seat:2}
```

动态座号可写入 `storage cardtable:deal seat`，再用 `function cardtable:animation/deal/launch with storage cardtable:deal` 调用。后台保存真实手牌、飞行牌仅作表现时，在 launch 前给待配置物品加 `ct.visual_only`，通用层会阻止拾取并清理。

## HUD、字体与叠牌

私有手牌优先复用 BetterTitle。面板按玩家独立分配并稳定持有，刷新手牌、Q 道具归位不能重置面板编号；退局时只释放本游戏面板。牌面、数量、选中状态和操作物名称留出独立空间，支持多行或叠牌后的最大手牌数。

26.2 的 `FontTexture` 为 256×256，**单个原始字形切片的宽、高均须不超过 256 像素**；大 PNG 分成多个合规字形可以使用。BitmapProvider 的 `height` 只改变显示比例，不缩小上传像素。物品牌面可保留高分辨率，HUD 和对话框另导出小尺寸字体纹理，并检查 `chars` 行列、切片、`height` 与 `ascent`。

叠牌的可见尺寸、实际字距、负宽回退、层间距及点击区域使用同一套几何计算；字距按真实 alpha 边界与字体缩放核对。透明留白或接缝应修正源切片及透明像素，不能单靠增加负宽掩盖错位。验证首张、后续衔接、选中边框、数量及每张牌的点击对应。

## 坐标、日志与性能

大型棋盘优先使用单交互面加视线与棋盘平面求交、坐标换算；空交点不逐个创建交互和展示实体，占地及高亮可合并绘制。四／八人桌、横竖方向、棋盘边框、坐标文字、落点与吃子区共用坐标定义，测试边角和最大尺寸；密集点位提供坐标输入或确认方式。

六边形棋盘可参考 `catan` 的独立地块／顶点／边拓扑，不能套用最近方格映射。现有五子棋／围棋射线用有界二分定位平面，不是解析求交；复用时保留角度、范围、坐标溢出及桌号校验。服务端可算到远端不代表客户端能右键到，须提供专属道具 Q 瞄准入口。公共合法提示只依据公开棋面，支付能力等私有信息在本人菜单说明，提交时再完整校验。

文本动画库已内置。将参数和文本组件写入 `storage fimel_anim_text:runtime positional.animation.data` 后，在目标位置调用 `cardtable:animation/text/load`。适配器避免中文重复经过宏参数；调用方仍需记录生成的 `fca_id` 并按桌号、动画实例号清理。参考 `fast_card:transition/round_title`，新游戏不调用其历史兼容适配入口。

提供 `<game_ns>:log {text:"消息"}`，仅向带 `ct.debug` 标签的玩家发送。记录开局拒绝、阶段切换、关键操作、结算与清理，不因入座自动添加 Debug 标签，不逐刻刷日志。注释、日志和玩家提示使用中文。

每刻只处理活跃状态控制器、即时输入及短暂飞行实体。离线检查、人数重算、迁移等维护放到 10 或 20 刻周期；避免无状态筛选地扫描全部实体、物品栏或每刻重建界面。

人机、规则枚举和大棋盘扫描须有工作上界，耗时搜索按刻推进；队列与缓存绑定桌号、局面版本和回合，局面改变、悔棋、结束或重载时取消过期搜索。模拟只能修改临时缓存并完整还原，选择结果仍经真实提交入口复验。单人模式按规则处理整回合悔棋，思考与动画是否计时保持一致。

遵守默认 `max_command_sequence_length=65536`，同时验证两桌交错的输入、搜索和动画；不能靠提高全服命令上限维持新游戏。

## 加载与升级

使用 `#version <p>_ctx` 区分首次安装和逐版迁移。安装只执行一次，升级只增补或迁移数据；`/reload` 保留手牌、回合、身份、设置和结算计时，恢复所需入口但不能重新发牌或抽题。修改实体标签或布局时，为旧存档提供一次性兼容迁移。

悔棋、复盘与重载所需快照须涵盖完整规则状态：棋面或手牌、私密身份、盖面、轮次、阶段、计时、得分、被吃区域及重复局面等裁判历史。快照与真实提交处于同一边界，模拟不写入正式历史；重载可取消并重建表现与搜索，但必须接续已提交结果。

## 生成器与发布

生成器按职责维护数据、模型、纹理、字体和音效，重复执行结果一致；调用公共修补脚本须在完整生成流程中登记，不能靠手改产物维持。资源名表达颜色、棋种、角色或用途，避免无规律连续编号；复用现有资源前核对尺寸、UV、朝向和来源署名，新建模型保留可编辑源文件。

检查数据包与资源包的版本信息、模型／纹理／字体／音效引用及 `sounds.json`，自制或引用资源记录来源与重建方式。发布时按当次目录白名单核对 ZIP 根目录，不夹带工具、`docs/`、`.source/` 或临时测试世界；仓库保留制作源文件及完整文档。
