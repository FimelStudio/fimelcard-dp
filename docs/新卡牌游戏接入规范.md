# 新卡牌游戏接入规范

适用 Minecraft Java 26.3。新增游戏先分配连续的 `<game_id>`、独立命名空间 `<game_ns>` 和短前缀 `<p>`；已用编号与命名空间见[文档索引](README.md)。

## 模块与实例边界

`cardtable` 管理桌面、座位、人数、菜单、结束投票、公共动画及游戏分派；游戏模块管理牌组、回合、玩家状态、计分、设置与专属清理。游戏不得复制通用发牌逻辑、修改座位或删除通用控制器。

控制器为 `@e[type=minecraft:marker,tag=ct.controller]`，游戏入口默认以它为执行者、以桌心为执行位置。

| 控制器记分项 | 含义 |
| --- | --- |
| `ct_id` | 服务器内唯一桌号 |
| `ct_state` | 0 大厅，1 游戏中 |
| `ct_game` | 当前游戏编号 |
| `ct_capacity` | 桌型容量 4 或 8 |
| `ct_joined` | 当前参与人数 |
| `ct_start` | 开局成功握手，初始 0，游戏成功后置 1 |
| `ct_votes` | 当前有效结束票数 |

参与玩家带 `ct.player`，其 `ct_id` 为桌号、`ct_seat` 为实际座号。八座按北 1～2、东 3～4、南 5～6、西 7～8 顺时针排列。人数和座号分开处理：五人局也可能坐在 6～8 号座，发牌、邻座、提示、投票和显示均须跳过空座。游戏中下马不代表退出。

所有长期实体须带专属标签和桌号，清理同时校验两者。距离仅用于缩小范围，不能代替实例归属；跨刻临时状态也须绑定桌号。同步临时标签应在同一函数链内完成清旧、标记、使用和移除。

```mcfunction
# 控制器定位本桌玩家；不要仅用 nearest 认定归属
scoreboard players operation #ctx_id <p>_ctx = @s ct_id
execute as @a[tag=ct.player] if score @s ct_id = #ctx_id <p>_ctx run ...
```

专属记分项、标签、storage 统一使用本游戏前缀或命名空间，例如 `<p>_state`、`<p>.controller`、`<game_ns>:runtime`。记分项目标名建议不超过 16 字符。

## 生命周期接口

推荐沿用 `function/game/`、`player/`、`settings/`、`rules/`、`deck/`、`deal/`、`round/`、`debug/` 的现有职责划分。

| 接口 | 执行者与要求 |
| --- | --- |
| `game/init_table` | 控制器；幂等，只修正缺失或越界的持久设置，不能重置活跃对局 |
| `game/start` | 控制器；自行检查人数、快捷栏等条件，失败保持 `ct_start=0` 并返回失败，全部初始化成功后置 1 |
| `game/finish` | 控制器；锁定结束状态、展示结果、清理游戏，最后返回大厅 |
| `game/end_vote` | 控制器；通用层已判定票数，执行一次提前结束流程 |
| `game/abort` | 控制器；任意阶段可安全中止，完整清理后返回大厅 |
| `admin/abort` | 玩家；定位同维度 8 格内最近一场本游戏，无目标提示并返回失败，切换执行者和位置后调用 `game/abort` |
| `game/player_left` | 控制器；决定离线后继续、淘汰或中止的行为 |
| `player/clear_state` | 玩家；仅清理该玩家的专属物品、标签和临时分数 |
| `settings/open` | 控制器；接收玩家为 `ct.settings_actor` |
| `rules/show` | 控制器；接收玩家为 `ct.rules_actor` |

开局时复制 `ct_id`、`ct_seat` 到游戏运行状态，不修改通用归属。人数必须同时满足本游戏范围与桌型容量；游戏加载入口不得替代开局入口。

结束流程须防重复进入。清理本游戏手牌、牌堆、掉落物、展示与交互实体、文字动画以及公共发牌动画，移除专属控制器标签，最后调用：

```mcfunction
function cardtable:animation/deal/clear
function cardtable:game/return_lobby
```

不得删除方块桌、玩家装饰、`ct.controller`、`ct.seat` 或其他桌状态。若清理期间调用人数重算等通用维护，先锁定结束状态，避免重新触发结束投票。不要在结算过程中重复初始化计时器。

## 注册点

新增游戏时逐项检查以下文件，保持编号从 1 连续排列：

| 文件（相对 `data/cardtable/function/`） | 更新内容 |
| --- | --- |
| `load.mcfunction` | `#game_count ct_ctx` |
| `menu/picker/show4`、`show8`、`open`、`handle` | 选择按钮、人数提示、提交值与编号校验 |
| `menu/select_game` | 切换消息及日志 |
| `menu/game_name_<game_ns>`、`menu/render` | 大厅名称与未知编号兜底 |
| `game/init_selected` | `game/init_table` 分派 |
| `game/start` | 开局分派与握手 |
| `game/open_settings` | 设置入口分派 |
| `game/open_rules` | 规则入口分派 |
| `vote/finish` | 已达门槛后的 `game/end_vote` 分派 |
| `table/remove` | 活跃对局的 `game/abort` 分派 |
| `game/remove_offline_player` | 玩家专属清理分派 |

表中省略的函数文件扩展名均为 `.mcfunction`。在 `data/minecraft/tags/function/load.json`、`tick.json` 各登记一次本游戏总入口，并更新根 README 的游戏链接及文档索引。游戏人数变化须同步两种桌型的菜单和规则。

## 设置与交互

设置最终保存在本桌控制器上，不能用全局 storage 充当所有桌的持久设置。打开设置时初始化缺省值，保存打开时的桌号，再给当前玩家临时启用独立 trigger。

保存前验证：玩家仍属于原桌、控制器存在且处于大厅、仍选中本游戏、输入值合法。切桌、开局、离座、重载后的旧窗口不能覆盖当前状态。多个输入编码为整数时，记录编码方式并检查边界。

规则使用 `pause:false` 的只读 Dialog，说明人数、牌组、操作、胜负、计分及特殊情况。普通玩家通过交互和 trigger 操作，无需函数权限。

| `ct_kind` | 通用用途 |
| --- | --- |
| 11～18 | 座椅，10 加座号 |
| 21 / 22 / 23 | 切换游戏 / 开始 / 设置 |
| 30 / 31 | 结束投票 / 常驻规则 |

新增通用交互须登记唯一编号，提供右键与攻击两个 advancement，并在奖励函数开头撤销它们。游戏专属按钮使用自己的 advancement 和状态，不重复生成通用规则按钮。

结束投票由通用层按当前在线真人统计：四座桌为 `min(3, 人数)`，八座桌为 `floor(人数/2)+1`；重复投票和已离桌者的票不得计入。游戏直接接收通过后的结束回调。

## 卡牌与公共发牌动画

卡牌逻辑依据游戏专属 `custom_data`，`item_model` 仅控制外观、`item_name` 仅控制名称。清理时按专属数据匹配，不能误删普通纸或其他游戏物品。

公共入口位于 `cardtable:animation/deal/`，调用者必须是本桌控制器且位于桌心：

| 入口 | 作用 |
| --- | --- |
| `box/spawn` | 在桌心上方生成小牌盒 |
| `box/grow` / `box/shrink` | 10 刻内放大 / 缩小，生成后至少隔 1 刻再放大 |
| `box/clear` | 清除本桌牌盒 |
| `spawn_card` | 生成唯一待配置物品，标记 `ct.new_dealt_card` |
| `sound` | 向本桌玩家播放发牌音效 |
| `launch {seat:N}` | 设置接收者与动量，送往实际 N 号座 |
| `clear` | 清理本桌公共动画与临时状态 |

游戏负责牌面、牌数、顺序、间隔及完成回调；通用 tick 负责飞行与 6 刻兜底送达，不得另写重复维护。

```mcfunction
function cardtable:animation/deal/spawn_card
item replace entity @e[type=minecraft:item,tag=ct.new_dealt_card,distance=..2,limit=1] contents with minecraft:paper[minecraft:item_model="<model>",minecraft:item_name="<name>",minecraft:custom_data={<game_ns>:{card:1b,id:1}},minecraft:max_stack_size=1]
function cardtable:animation/deal/sound
function cardtable:animation/deal/launch {seat:2}
```

动态座号可写入 `storage cardtable:deal seat`，再用 `function cardtable:animation/deal/launch with storage cardtable:deal` 调用。后台保存真实手牌、飞行牌仅作表现时，在 launch 前给待配置物品加 `ct.visual_only`，通用层会阻止拾取并清理。

## 文字动画、日志与性能

文本动画库已内置。将参数和文本组件写入 `storage fimel_anim_text:runtime positional.animation.data` 后，在目标位置调用 `cardtable:animation/text/load`。适配器避免中文重复经过宏参数；调用方仍需记录生成的 `fca_id` 并按桌号、动画实例号清理。参考 `fast_card:transition/round_title`，新游戏不调用其历史兼容适配入口。

提供 `<game_ns>:log {text:"消息"}`，仅向带 `ct.debug` 标签的玩家发送。记录开局拒绝、阶段切换、关键操作、结算与清理，不因入座自动添加 Debug 标签，不逐刻刷日志。注释、日志和玩家提示使用中文。

每刻只处理活跃状态控制器、即时输入及短暂飞行实体。离线检查、人数重算、迁移等维护放到 10 或 20 刻周期；避免无状态筛选地扫描全部实体、物品栏或每刻重建界面。

## 加载与升级

使用 `#version <p>_ctx` 区分首次安装和逐版迁移。安装只执行一次，升级只增补或迁移数据；`/reload` 保留手牌、回合、身份、设置和结算计时，恢复所需入口但不能重新发牌或抽题。修改实体标签或布局时，为旧存档提供一次性兼容迁移。

## 验收

按[验收清单](验收清单.md)完成静态检查和实际联机复测；新增游戏至少覆盖人数边界、稀疏座位、普通玩家操作、每个阶段中止与重载、正常结束及两桌隔离。
