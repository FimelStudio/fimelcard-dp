# 座位自动恢复

## 原因与修改

存档只读检查发现，四人桌缺失的2号座位存在于离线玩家的 RootVehicle 中，世界实体文件中只剩1、3、4号座位。玩家坐在交互实体上退出后，座椅可能随玩家载具保存，原有牌桌维护没有补回缺座。

- 通用牌桌在 reload 及每半秒维护时，按桌号和座号补回缺失的交互实体，适用于四座和八座。
- 完整桌子覆盖的区块加载后才执行恢复，避免把未加载座位误判成缺失。
- 上线带回旧载具后，优先保留有乘客的座位，删除重复空座；多个副本都有乘客时，等离座后再收回。
- 不重建桌面或实体椅子，不改游戏进度、玩家身份和正常占座。
- 四人桌入座调整朝向改为使用玩家传送后的坐标。
- 本次未改写任何玩家或世界存档文件，也不主动删除已移除桌子遗留在离线玩家存档中的载具。

## 自动检查

运行 `node tools/check_seat_recovery.mjs`，执行实际修复函数的指令子集，验证292种缺座组合、重复维护、上线带回座位、占用副本、跨桌隔离及区块未加载情形。

## 游戏内验收

1. 在已有四人桌附近执行 `/reload`，原缺座恢复可点击，无需重建桌子。
2. 玩家坐下后退出，其他人留在桌边；约半秒后空座可再次使用。
3. 原玩家重新进入，检查对应座位没有重叠的空交互实体，仍能正常坐下和离座。
4. 让另一人使用补回的座位后，原玩家重进；当前乘坐者不能被修复逻辑强制踢下。
5. 四人桌、八人桌同时测试，游戏中执行 reload：其余座位、牌局状态和桌面不变。
6. 桌子跨区块边界时卸载再加载，重复几次，确认座位不累积。

自动检查不能替代 Minecraft 服务器加载与多人退出/重进测试。
