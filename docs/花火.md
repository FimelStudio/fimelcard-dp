# 花火

2～5 人合作推理游戏。你能看见其他人的真实手牌，却只能通过队友的提示了解自己的牌；全队合力按 `1 → 2 → 3 → 4 → 5` 接出各色烟花，争取满分。

游戏编号 `3`，命名空间 `hanabi`。五人局使用八座桌，可任坐五个座位。安装、建桌和通用操作见 [README](../README.md)。

## 开局与信息

- 开局前清空快捷栏第 1～5 格、第 9 格及副手。2～3 人每人 5 张，4～5 人每人 4 张，首位玩家随机。
- 基础牌库共 50 张：白、红、蓝、黄、绿每色各 10 张，数量为 `1×3、2×2、3×2、4×2、5×1`。
- 左上角显示其他玩家的真实手牌；自己的快捷栏仅显示已知信息：牌背、已知颜色、已知数字，或两者都已知的完整牌面。补进的新牌会重置已知信息。
- 桌心显示提示、失误、牌库、奖励余量及得分；点击桌角“弃牌堆”可查看按弃出顺序排列的公开弃牌。
- 请通过正式提示传递牌面信息，不要通过聊天、语音或行动暗示绕过隐藏手牌规则。

## 回合操作

轮到自己时，完成以下一种行动后交棒：

| 行动 | 操作 | 效果 |
| --- | --- | --- |
| 出牌 | 选中手牌按 **F** | 正好接上该色下一数字则成功；否则进入弃牌堆并增加 1 次失误 |
| 弃牌 | 选中手牌按 **Q** | 进入弃牌堆，恢复 1 枚提示；提示已满时仍可弃牌 |
| 提示 | 选中第 9 格“提示队友”按 **Q** | 选择另一名玩家，再选择一种颜色或一个数字；消耗 1 枚提示 |

提示必须至少命中一张牌，并同时指出目标手中所有符合条件的牌，不能提示自己。取消或关闭提示窗口不会消耗提示，可重新打开。没有提示标记时不能提示。

出牌或弃牌后，牌库有牌便补回原手牌位；成功完成数字 5 还会恢复 1 枚提示并处理奖励。所有提示恢复都不超过本桌上限。

## 奖励与结束

奖励独立于普通牌库，固定 6 张，不放回抽取。每完成一列烟花，完成者随机抽取一张剩余奖励并立即处理，不占普通手牌或额外回合。

| 奖励 | 数量 | 效果 |
| --- | --- | --- |
| 提示恢复 | 2 | 恢复 1 枚提示 |
| 弃牌恢复 | 2 | 从公开弃牌堆选一张放回普通牌库；弃牌堆为空时无效果 |
| 完全提示 | 1 | 选择另一名玩家的一张牌，同时公开颜色和数字 |
| 风险调整 | 1 | 选择 0～2，同时增加等量的提示和失误；失误达到上限会立即失败 |

需要选择的奖励必须完成后才能继续普通行动。牌库耗尽后继续处理所有普通手牌，空手玩家自动跳过。

- **失误达到上限**：立即失败，得 0 分。
- **所有烟花完成**：立即以 25 分获胜；彩色风暴为 30 分。
- **牌库及所有普通手牌耗尽**：各色烟花堆顶数字相加为最终分数，并播放对应档位的终场烟花。

## 设置与命令

大厅点击“游戏设置”修改，设置仅属于本桌，开局后锁定：提示上限 **1～32**（默认 8）、失误上限 **1～9**（默认 3）、彩色风暴（默认关闭）。彩色风暴加入彩色 1～5 各一张，彩色可独立提示，牌库变为 55 张、满分 30 分。

正常操作使用 F、Q 和对话框。以下 trigger 模板仅在当前玩家、回合及窗口允许时有效，不能越过合法性检查：

```mcfunction
# 打开提示；取消提示
/trigger hb_action set 300
/trigger hb_action set 390
# 选目标座位 1～8：301～308
/trigger hb_action set 301
# 提示颜色：401白、402红、403蓝、404黄、405绿、406彩色
/trigger hb_action set 401
# 提示数字 1～5：501～505
/trigger hb_action set 501
```

管理员在牌桌 8 格内执行以下命令，操作同维度最近一场花火，无需填写桌号。中止会清理本局并返回大厅，保留牌桌；精确指定桌号见[主说明](../README.md)。

```mcfunction
/function hanabi:admin/abort
# 查看目标桌运行状态：0初始化、1发牌、2回合、3结算
/scoreboard players get @e[type=minecraft:marker,tag=hb.controller,distance=..8,sort=nearest,limit=1] hb_state
# 查看事件日志；关闭时将 add 改为 remove
/tag @s add ct.debug
```

## 维护入口

真实牌以服务端 marker 为准，物品和显示只负责交互。左侧手牌使用已合并的 BetterTitle，烟花使用已合并的 SK Firework，无需重复安装前置。本分支需搭配相应版本的资源包，1.21.11 使用配套资源包的 `rendertype_text` 文字着色器。

- 资源重建：[生成牌面](../tools/generate_hanabi_assets.ps1)、[彩色风暴纹理](../tools/generate_hanabi_storm_textures.ps1)、[奖励牌纹理](../tools/generate_hanabi_tool_textures.ps1)。源图保存在资源包 `.source/hanabi`，物品纹理保持 256×256。
- 特效检查：`/function hanabi:test/firework_success`、`hanabi:test/firework_finale`、`hanabi:test/firework_storm_success`、`hanabi:test/firework_storm_finale`；资源测试牌：`/function hanabi:test/tool_cards`。
- 奖励扩展在 `#hanabi:reward_cards` 注册创建函数，调用 `hanabi:reward/deck/add {reward:100,copies:1}` 加入独立奖励池。编号从 100 起、数量 1～32；在 `#hanabi:reward_resolve` 处理效果，完成后调用 `hanabi:reward/finish`。异步效果等待期间给控制器添加 `hb.reward_external_wait`，完成时移除。

联机检查统一见 [验收清单](验收清单.md)。
