# 骷髅牌接入说明与验收

游戏编号9，命名空间skull，前缀sk。按《骷髅牌规则.md》接入四座和八座牌桌，支持2至6人（四座最多4人）。

## 玩家操作
- 开局清空快捷栏，每人3张花牌（黑桃A，card:poker/c_a）及1张骷髅牌（小丑牌，card:poker/joker）。四张牌使用独立编号。
- 选中要扣的手牌按Q出牌；叫号、翻牌和弃牌使用对话框，手持紫色染料按Q打开。无效阶段、未轮到、重复首次扣牌或过期的卡牌会返还。
- 每轮先同时秘密扣一张；随后按北、东、南、西座位顺时针轮流加牌或叫号，跳过空座。
- 叫号直接点击具体数字。下限是“自己扣牌数”和“当前最高叫号加一”的较大者，上限是桌上总牌数。
- 首次叫号后不能再加牌，只能提高叫号或放弃。放弃者的扣牌仍参与挑战。叫到桌上总数直接开始挑战。
- 挑战者先自动逐张翻自己的牌；自己翻完后逐次选择其他玩家的堆顶。只公开实际翻出的牌。
- 达到目标且全为花牌，获得一次胜利。翻到骷髅立即停止。
- 他人的骷髅：从挑战者全部剩余卡牌中等概率随机永久弃一张；自己的骷髅：私密选择永久弃一张，包括已经扣下的牌。
- 弃牌内容仅本人可见；无牌者清理手牌并离座淘汰。挑战者作为下一轮起始玩家；淘汰则顺时针下一人开始。
- 每轮结算后2秒自动继续。两次成功或成为最后一名有牌的玩家立即获胜。

## 显示与边界
- 桌面中央仿照出包魔法师的文字面板，仅显示“玩家名：本轮出牌数量”；翻开牌后数量仍表示本轮曾扣下的总数，下一轮归零。
- 不创建桌面牌堆、翻牌模型或其他长期卡牌展示实体。黑桃A和小丑模型用于手牌与开局公共发牌动画。
- 真实牌型、权威手牌、永久拥有的卡牌和堆顶顺序保存在对应桌子的控制器中。
- 临时UI缓冲只用于同步构建；所有交互校验桌号、玩家、阶段、轮到的座位和交互序号。
- 每轮首次扣牌允许多人同时按Q，重复提交由已扣牌标志阻止；卡牌带交互序号，旧回合或旧行动中丢出的牌不能跨阶段连续扣牌。
- 中途掉线会中止本桌；正常淘汰经通用牌桌接口离座并重算人数。
- 重载不重置手牌、扣牌顺序、弃牌、叫号和胜利次数；恢复原阶段、界面及专属物品。
- 结束投票、正常结束和管理员移除都会清理本桌手牌、工具、掉落物、中央文字与发牌动画。
- 规则补充：叫号不得低于自己的扣牌数，以保证“先翻完自己所有牌”；挑战者淘汰时顺延起始座位。设置入口展示固定标准规则。

## 自动检查
运行 `node tools/check_skull.mjs`。
包含函数引用及括号、牌桌全部注册、牌面资源引用、无桌面牌堆模型、叫号边界、座位轮换和1200局固定种子规则模拟。
检查只能验证静态结构与规则模型，不能证明Minecraft命令已被引擎成功加载。

## 游戏内验收
- [ ] /reload无函数解析错误，牌桌可选择第9个游戏；2、3、4人及不连续座位均可开始。
- [ ] 开局发牌动画只有短暂牌盒与卡牌，完成后无小牌、牌堆或额外模型残留。
- [ ] 手中花牌是黑桃A，骷髅是小丑；中心仅显示名字和出牌数量。
- [ ] 同时扣第一张，重复点按钮不多出牌；未轮到的人不能加牌。
- [ ] 无手牌只能叫号；按钮范围正确；叫号后不再有加牌选项；旧按钮无效。
- [ ] 放弃竞标后不能重新参加，但仍可被翻牌；叫到总数直接进入挑战。
- [ ] 必须先从顶到下翻自己所有牌，再选别人，每次只能翻最上面的一张。
- [ ] 己方骷髅自选弃牌和他人骷髅随机弃牌分别正确，弃牌内容没有广播给其他人。
- [ ] 弃掉的牌后续不再发回；可以只剩花或只剩骷髅；最后一张被弃后正确离座淘汰。
- [ ] 两次成功和最后存活两条胜利路径都能结束；挑战者淘汰后的首家正确顺延。
- [ ] Q丢出所选黑桃A或小丑牌会正确扣牌；未轮到、首次重复和叫号后出牌均返还；连续丢牌不能跨行动多扣。紫色染料仍打开对话框，不算扣牌。
- [ ] 在发牌、首次扣牌、加牌、叫号、翻牌、自选弃牌及结算阶段重载，都保持进度。
- [ ] 两桌同时操作不串桌；中止其中一桌不影响另一桌。
- [ ] 每个阶段分别测试掉线、投票结束和移除牌桌，专属物品与实体完全清理。

## 六人扩展验收

- 六人任意入座，包含7、8号座；每人动画发四张，结束后没有残留小牌。
- 叫号可达到24张，20至24张不会误触放弃，放弃与旧版动作编号保持兼容。
- 翻牌列表包含高号座的真实姓名；下一轮回收所有存活者的牌，淘汰后跳过空座。
- 七人拒绝开局，原两至四人流程保留。
