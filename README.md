# Fimel Card 26.2

版本分支：`26.2`；配套数据包与资源包请使用同名分支。内容同步自 `main` 的 v1.1。

Minecraft Java 26.2 多人卡牌桌游数据包。作者：歪浪Ylong、水晶Cesmos。

[下载数据包和资源包](https://studiofimel.com/#/works/fimel-card) · [完整文档](https://github.com/FimelStudio/fimelcard-dp/blob/26.2/docs/README.md) · [数据包仓库](https://github.com/FimelStudio/fimelcard-dp/tree/26.2) · [资源包仓库](https://github.com/FimelStudio/fimelcard-rp/tree/26.2)

第一次接触这些桌游，请看[23 个游戏的新手说明书与组件图鉴](docs/releases/rules/README.md)：每个游戏一份，包含准备、完整回合、操作、卡牌／棋子效果和资源实图。

## 安装与游玩前提

1. 将 `fimelcard-datapack` 放入存档的 `datapacks`，确认 `pack.mcmeta` 位于数据包根目录。
2. 每位玩家将配套的 `fimelcard-resourcepack` 放入客户端 `resourcepacks` 并启用。
3. 进入世界执行 `/reload`；更新资源包后按 `F3+T`。
4. 按各游戏文档腾空所需快捷栏，不确定时可清空九格。UNO 在本人出牌回合使用第 1 格；国际象棋、中国象棋、五子棋和围棋使用最后一格对局菜单；飞行棋本人回合第 1 格按 Q 投骰。情书前两格直接显示手牌，朝向目标后按 Q 打出；璀璨宝石直接右键桌面宝石与卡牌，快捷栏显示宝石和预定牌；卡坦岛使用九格建筑、交易、回合和骰子操作物。命悬一线需腾空第 1～6 格和最后一格；阿瓦隆需第 1、2、8 格，花火还需腾空副手。创建、删除和调试命令需要命令权限，局内游玩的权限要求见下表。

胡闹运动会需腾空快捷栏九格，并为队伍棋子留出背包空间；招募、出场与技能目标都使用立体棋子，轮到自己时按 Q 投骰，技能目标棋子按 Q 一次选定。天才预测点数时前六格直接显示六种骰面，第七格可不预测。普通／狂野棋盘带立体看台与灯架，棋子上方以竖直朝向的玩家皮肤头像标明归属。

情书默认朝向选人，目标保留 3 秒，actionbar 显示姓名；也可在开局前设置为头颅精准选择，此时需腾空九格，Q 出牌后再 Q 玩家头颅确认，最后一格可取消。

部分游戏使用到了前置 [文本动画库](https://space.bilibili.com/648638421)、[BetterTitle](https://github.com/Huoyuyuyu/BetterTitle)、[SK Firework](https://space.bilibili.com/1546917549)，无需另装前置数据包。

牌桌皮肤使用到了16bit制作组的[NyaaWork喵工坊家具](https://space.bilibili.com/2907002)。本包仅将使用到的家具模型加至资源包中，资源归原作者所有。

## 创建、删除牌桌

在空地执行创建命令，当前位置的高度对应桌面方块层。

**建桌的最小检查距离为 6 格**，按建桌执行位置到已有桌心计算，并非两桌边缘之间需要空出 6 格。四座桌连座椅占地 **5×5**，八座桌占地 **6×6**；同一高度沿直线并排摆放时，两张八座桌想留一格通道，桌心间距至少取 **7 格**。新桌会对齐方块网格，摆放时以最终桌心位置为准。

```mcfunction
# 四座桌：3×3 桌面，含座椅占地 5×5
/function cardtable:admin/create

# 八座桌：4×4 桌面，含座椅占地 6×6
/function cardtable:admin/create8

# 删除 8 格内最近一张牌桌的会话、座椅和交互实体
/function cardtable:admin/remove
```

删除会中止该桌游戏，保留方块桌面；使用主题皮肤的桌子先恢复为默认木桌。剩余方块可自行拆除。

已有桌面可用以下命令注册，不改动方块：四座桌站在 3×3 桌面中心方块上；八座桌站在 4×4 桌面的中心交界点上。

```mcfunction
/function cardtable:admin/create_safe
/function cardtable:admin/create8_safe
```

右键空座入座，在中央选择游戏、调整设置并开始；桌边“规则介绍”随时可看。大厅潜行下马即离桌；游戏中下马保留参与身份，右键原座可坐回。点击“结束游戏”投票提前结束，投票进度在聊天栏提示。

所有游戏设置统一为单页文本选项，点击立即生效，数字用加减调整；“牌桌皮肤”下面可调整**椅子数量**：默认四座／八座全开，仅大厅可改；不能少于当前游戏最低人数和已入座人数，保留已坐人的椅子。八座桌一侧只剩一把椅子时自动居中。切换游戏会自动补足其最低座位数。

**任一本局玩家离线，整桌暂停，等待原玩家全部上线后自动继续，不会超时结束。** 暂停期间冻结操作、计时、人机和发牌，可通过桌边投票或管理员中止命令结束。若离线期间牌局已结束，玩家重进时自动清除上局道具、身份与标签。所有游戏采用相同规则。

## 卸载与重新安装

卸载前请让参与过游戏的玩家上线，并加载放有牌桌的区块，再由管理员执行：

```mcfunction
/function cardtable:admin/uninstall
```

该命令会结束所有已加载牌桌的游戏、让在线玩家离座并回收本包道具与界面，删除各维度已加载的功能实体，取消本包延迟任务，清空游戏与内置库的 storage 内容，最后删除本包计分板。清理分刻执行，请等待聊天栏出现“卸载完成”，期间不要移除数据包。只撤销已记录为由本包新增的区块强加载，保留原有强加载、外部数据包状态和玩家普通物品。主题皮肤恢复为默认木桌，方块桌面和玩家建筑保留。

原版函数无法直接改写离线玩家的背包、标签或未加载区块里的实体；未满足上述上线、加载条件的部分不在本次清理范围内。执行命令本身不会删除数据包 ZIP／文件夹，完成后将它从 `datapacks` 移除，再执行 `/reload`。若文件仍在，直接 `/reload` 会重新安装。

以后将数据包重新放回并 `/reload`，即可从全新状态安装、创建牌桌；资源包可继续使用。开发者新增游戏或资源后，应最后运行 `python tools/build_uninstall.py`，更新自动清理清单及入口护栏。

v1.1 的[更新日志](docs/releases/v1.1/更新日志.md)与[发布页正文](docs/releases/v1.1/发布页正文.md)也包含卸载说明。

## 调试与局内命令模板

以下由有权限的玩家在聊天栏执行。中止附近的游戏无需填写桌号：

```mcfunction
# 中止 8 格内最近一场斗地主，返回大厅并保留牌桌
/function doudizhu:admin/abort
```

上表游戏均支持 `/function <命名空间>:admin/abort`，例如阿瓦隆为 `/function avalon:admin/abort`，命名空间见[文档索引](docs/README.md)。命令只中止同维度 8 格内最近一场对应游戏，其他桌不受影响，无需填写桌号；各游戏文档提供完整模板。

需要精确指定某张桌子时，再查询自己所属的桌号：

```mcfunction
/scoreboard players get @s ct_id
```

将下面的 `1` 换成该桌号，可查询游戏编号或精确中止对局；`game/abort` 是供控制器执行的内部入口：

```mcfunction
/scoreboard players get @e[type=minecraft:marker,tag=ct.controller,scores={ct_id=1},limit=1] ct_game

# 中止这张桌子的斗地主并回大厅；其他游戏替换命名空间和游戏编号
/execute as @e[type=minecraft:marker,tag=ct.controller,scores={ct_id=1,ct_game=10,ct_state=1},limit=1] at @s run function doudizhu:game/abort
```

游戏编号与命名空间见[文档索引](docs/README.md)，可用命令见各游戏介绍。控制器命令在该桌所在维度、区块已加载时执行；`/trigger` 仅在游戏开放的阶段可用，具体参数见各游戏文档。

```mcfunction
# 自己接收 Debug 日志 / 停止接收
/tag @s add ct.debug
/tag @s remove ct.debug

# 手动测试日志
/function cardtable:log {text:"测试牌桌日志"}
```

只有带 `ct.debug` 标签的玩家接收日志，入座不会自动开启。卡桌时记录游戏名、桌号、操作阶段和日志；座位缺失可先尝试 `/reload`，仍无法继续时按对应游戏命令中止。

皮肤、表情包、语音及内置库资料见[牌桌与互动](docs/牌桌与互动.md)；开发见[新卡牌游戏接入规范](docs/新卡牌游戏接入规范.md)，发布前检查见[验收清单](docs/验收清单.md)。
